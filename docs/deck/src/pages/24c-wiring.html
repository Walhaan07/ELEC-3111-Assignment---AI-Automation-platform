What it is

Every arrow below is a promise one pair makes to another. Print this page, put it on the wall, and settle arguments with it.

Each section of Part 2 ended with a small strip showing what it receives and what it hands on. This is all of them at once. Nothing crosses a box boundary except the labelled arrows — that single rule is what lets four pairs work in four folders without waiting for each other.

Reading the picture as a work plan
Week 3–4Only the two purple boxes exist. A1 freezes ctx and the branch shape; everybody else writes against a written promise, not against code that exists yet. Week 5The blue and cyan boxes join, and the top arrow becomes real. This is the hard gate: the editor can save and reload a workflow. Week 8The right-hand purple box grows six new files at once. Nothing else changes — that is the payoff for §2.3b. Week 9–10The OAuth sub-box and the outward arrows from the nodes. D1 owns request.js; D2, A1 and A2 write nodes against it in parallel. Week 12The whole picture is put on one server (§2.7b) and measured against n8n running the same three workflows.
Use it like thisWhen two people disagree about where code should live, find the arrow it crosses. Code that translates between two boxes belongs to one of them, never both — that is what convert.ts, runner.js and request.js each are. If a new idea needs a new arrow, that is a ten-minute group conversation, not a pull request somebody discovers on Thursday.
