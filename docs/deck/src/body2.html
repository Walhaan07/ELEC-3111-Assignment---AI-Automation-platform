The words we will keep using

Most of the confusion in a project like this comes from words, not from ideas. These eight describe things you have already seen with your own eyes in n8n — we are only giving them their proper names so the rest of this document can be short.

WordWhat it means, plainlyWhere you met it in n8n
Workflow One complete automation, from the thing that starts it to the last thing it does. It is just a drawing: some boxes and some lines. Your weather automation. One tab, one name, one on/off switch.
Node One step in that drawing. A node takes some data in, does one job, and passes data out. Every node works the same way, whether it sends an email or adds two numbers. Every box you dragged from the panel on the left.
Trigger A special node with nothing before it. It is what starts a workflow — a clock reaching a certain time, or a message arriving from outside. Your Schedule Trigger. Also the Webhook node.
Item One single piece of data travelling between nodes — one row, one email, one order. Nodes always pass a list of items, even when the list has only one thing in it. The numbered rows in the OUTPUT panel when you clicked a node.
Canvas The big area where you drag boxes and draw lines between them. It is only a drawing tool — the canvas never runs anything itself. The grey grid that filled most of the n8n screen.
Execution
(a “run”)		 One occasion on which a workflow actually ran. Each run is recorded so you can look back at it: what came in, what each node produced, whether it worked. The Executions list, with green ticks and red crosses.
Expression A small piece of text inside a settings box, written between double braces, that gets replaced with real data just before the node runs. {{ $json.city }} — what appeared when you dragged a field into a box.
Credential A saved login for an outside service, stored once and reused by any node that needs it. Kept scrambled so that reading the database does not reveal it. The Credentials screen where you connected your accounts.
Why this matters more than it looksThree of these words carry the whole project. Node tells us what four of us will spend Weeks 8–10 writing. Item decides the shape of every piece of code we write, and cannot be changed later. And execution is the thing our database exists to remember. If those three are clear to everyone, the rest of this document is mostly detail.
Part 0 · The vocabulary0.2 — The words behind the screen
0.2

The words behind the screen

These eight describe machinery you used without seeing. When you opened n8n at localhost:5678, every one of these was already working for you.

WordWhat it means, plainlyWhere it was in n8n
Server A program that sits waiting and answers when something asks it a question. It does not have a screen; it just listens on a numbered door called a port. The thing you started, listening on port 5678.
API The list of questions a server agrees to answer, and the exact wording each one needs. Think of it as a menu: not the kitchen, just what you are allowed to order. Two of them at once — n8n's own, used by its screen, and the weather service's, used by your HTTP node.
Endpoint One single item on that menu. An address plus a verb — for example “GET me the list of workflows”, or “POST this new workflow and save it”. /rest/workflows, called every time you opened the workflow list.
Request &
response		 The question and the answer. One request goes out, one response comes back, and the conversation is over. Nothing stays connected in between. Every click you made sent one and waited for the other.
JSON A plain-text way of writing down data that both people and programs can read. Curly braces for a thing, square brackets for a list of things. The OUTPUT panel, and the file you get from “Download workflow”.
Database A program whose only job is to remember things after everything else has been switched off, and to find them again quickly. Quietly holding your workflows so they were still there tomorrow.
Token A temporary key that a service hands you after you log in, so that later requests do not need your password. Most expire after about an hour. What n8n silently refreshed behind your Google credential.
Container
(Docker)		 A program packed up with everything it needs to run, so it behaves identically on every machine. Started with one command, thrown away with another. docker run n8nio/n8n — why it worked first time.

What a workflow really is

A workflow feels like a picture. It is actually a piece of text — a list of boxes and a list of lines, written down in JSON. The picture is only how we look at it.

Familiar from n8nWhen you clicked “Download” on a workflow, n8n handed you a .json file. That file was the workflow — you could email it to a friend, they could import it, and the same picture appeared on their screen. Nothing else was needed. That is the single most important thing to understand before we start.
Why this is good newsBecause a workflow is just text, the two halves of our project can be built by different people at the same time. The canvas only has to produce this text; the engine only has to read it. Neither needs to know how the other works — they only have to agree on the shape above.
What it means for usOur database will store this text in a single column. Saving a workflow is one write; loading it is one read; making a copy is copying a row. Big commercial platforms do exactly the same thing, for exactly this reason.
